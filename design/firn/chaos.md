Decision: The chaos experiment orders each shared key group's operations through fixed-width unique APPEND tokens, placing SET and INCR in the same transaction as their token and checking complete replies and final values with an independent serial model, because a disconnected client's INCR may have executed without its reply and a final count alone cannot identify a duplicated or missing effect, instead of retrying ambiguous writes or using the server's persistence file as its own oracle ([experiment and checker](../../research/investigations/chaos/README.md#independent-checker)).

Decision: Each epoch uses new shared key groups while retaining all older groups and their checked expectations until the run ends, because bounded in-memory histories must not erase evidence of acknowledged data lost at a later restart, instead of clearing the database between fault cycles or retiring previously checked writes ([workload](../../research/investigations/chaos/README.md#workload-and-fault-schedule)).

Decision: The chaos report separates observed lost acknowledgments, inconsistencies, unrequested process exits, refused restarts, and actual exercised or skipped fault coverage, and labels a competitor's weaker durability policy without weakening firn's zero-loss criterion, because a server refusing to recover its file is a server finding and a known acknowledgment-before-append loss or a missing fault device still fails to establish the proposed day-long acceptance, instead of treating refused recovery as a harness panic or an expected failure or unsupported comparison as a passing result ([criterion](../../research/investigations/chaos/README.md#question-and-rejection-criterion-before-measurement)).

Decision: A lost write on an explicitly unfixed firn image carries the known acknowledgment-before-append label only when its complete reply precedes the current recorded SIGKILL by at most 10 ms and no active EIO overlaps its request-to-kill interval, using 10 ms as a diagnostic consistency criterion rather than a promised append-delay bound, because the second hosted run lost six writes within 0.504 ms of their signals, including two new writes after EIO recovery, and a healed fault before invocation supplies no evidence about those new writes, instead of disabling that label forever after the first EIO or calling every pre-fix loss the known cause; overlapping faults, older replies and missing evidence retain an investigation or unverified label without weakening acceptance ([loss attribution](../../research/investigations/chaos/README.md#second-hosted-observation-loss-attribution-2026-10-13)).

Decision: A chaos job heals or removes the shared fault device only when the device's saved mount path matches that job's unique mount, recording that identity before changing the mapper or writeback settings, because cancellation can interrupt setup before a workflow step completes and an unrelated job may own the singleton device, instead of inferring ownership from the device's existence or requiring setup to finish before cleanup is possible ([CI ownership](../../research/investigations/chaos/README.md#ci-and-ownership)).
