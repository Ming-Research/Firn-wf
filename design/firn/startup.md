Decision: firn reads Redis 7.2.16's configuration syntax with an optional initial configuration filename or stdin -, followed by command-line directives introduced by every -- argument, applies those directives after file directives, and refuses unknown directives, because ordinary Redis deployments need their startup settings to be applied or explicitly refused, instead of firn's four positional arguments or ignoring unknown directives. This invocation does not consume a -- argument as a preceding directive's value or accept a trailing stdin -, and a first argument beginning with a single dash is a configuration filename ([invocation](../../firn/README.md#build-and-run)).

Decision: pending Whitefoot's general host-path support tracked by firn-req-host-paths, firn opens command-line configuration paths through the standard relative-path interface relative to its working directory, accepts only . and ./ for dir, and refuses include and other directory values with diagnostics naming that gap, because these interim rules expose the unavailable capability while allowing startup configuration without changing directories, instead of creating directories or interpreting general paths through a private workaround. The interim scope follows owner card firn-q-ops-paths-interim and is reopened when the host-path request is resolved ([path limits](../../firn/README.md#build-and-run)).

Decision: firn accepts port, bind, timeout, appendonly, appendfilename, requirepass, auto-aof-rewrite-percentage, auto-aof-rewrite-min-size, dir within the interim path limits, maxmemory, maxmemory-policy, maxmemory-samples, maxmemory-eviction-tenacity, lfu-log-factor and lfu-decay-time as startup directives, plus the firn-only test directive below, because these settings control behavior firn implements and refusing other directives exposes compatibility still to be implemented, instead of silently accepting unsupported Redis directives even at their default values. Startup validates the six memory settings through CONFIG SET's own validation code because both entry points must accept the same values and report the same reasons, instead of maintaining a second parser ([supported directives](../../firn/README.md#build-and-run)).

Decision: firn accepts one dotted IPv4 bind address or * and refuses multiple addresses and space-split address forms, because its server currently listens on one IPv4 socket and accepting Redis's several-address form would promise listeners it does not open, instead of ignoring extra addresses or expanding this startup change to multiple listeners. This is a firn limitation, not a Whitefoot limitation: the pinned std::net interface provides IPv6 socket addresses and independent tcp_listen calls. An empty bind, with zero values or one empty value, disables the listener as in Redis; without another listener firn exits 1 with the ordinary no-listener diagnostic ([binding](../../firn/README.md#build-and-run)).

Decision: firn uses the firn-only firn-clients directive to accept N clients then stop, with zero meaning no limit, because tests need a bounded server lifetime and a distinctive directive keeps this facility separate from Redis deployment settings, instead of retaining the positional client count ([test invocation](../../firn/README.md#build-and-run)).

Decision: firn refuses a naked argument after the configuration filename and before any -- directive, even when Redis would quote those arguments into a valid directive such as timeout 3, because an explicit -- boundary makes a misplaced extra filename or legacy positional argument an error, instead of Redis's implicit command-line configuration-line construction. Values following a -- directive remain its values until the next -- argument ([argument boundaries](../../firn/README.md#build-and-run)).
