Decision: firn answers both RESP2 and RESP3, a connection keeping the version HELLO last selected in its client record and every reply taking its type from that version in the shared reply writers (null, map, set, double, verbatim text and the member-and-score or field-and-value pairs Redis nests under RESP3), as Redis 7.0.15 chooses each reply's type from the client's protocol in its own writers, because two of the three selected consumers' clients, redis-py 8 and node-redis 6, open every connection with HELLO 3 and stop when it is refused ([consumers](../../research/investigations/consumers/README.md#what-the-milestone-needs-from-firn)), instead of refusing HELLO 3 as firn did.

Rejected:
- A second reply writer per protocol, each command choosing one: rejected because each command would write its reply twice, while the reply's shape is the same under both versions and only the type of a few elements changes, which Redis decides in its shared writers.
- Translating RESP2 replies into RESP3 after a command writes them: rejected because a RESP2 reply has lost the types RESP3 needs, a map and an array of field-value pairs and a double and a bulk string being written alike.
