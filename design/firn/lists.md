Decision: Firn provisionally keeps the store-wide ceiling of 4294967296 (2^32) elements for lists, shared with hashes and sets through `pkg::store::ceiling`, because one explicit capacity policy governs the boxed ring of owned byte buffers used by a list and the bounded hash maps used by hashes and sets, and no selected workload needs a larger collection, instead of giving lists a separate larger bound to match Redis 7.2.16 on 64-bit. List constructors and growth take that constant, while hash and set representations take it as a const parameter; changing the shared constant therefore changes the list limit too. The bound is a storage policy, not a consequence of a 32-bit list length representation. Its sufficiency for future selected workloads remains uncertain; reopen the shared ceiling and the affected representations when a selected workload needs more than 4294967296 elements.

Decision: A list command that would exceed the element ceiling returns an ERR reply naming the limit before changing any entry or access metadata, because a command-level refusal must leave the dataset available for inspection or retry without reconstructing an intermediate state. Admission covers every element of a multi-element push, and a move checks its destination before popping its source. A same-list rotation needs no additional room; LINSERT with an absent pivot still returns -1 because it adds nothing.

Rejected:
- Dropping elements while returning success: rejected because clients cannot distinguish lost data from an accepted write, so a successful reply cannot establish that the submitted value was retained.
- Partially inserting a multi-element push before returning an error: rejected because retrying the same command would duplicate the accepted prefix, while the error gives the client no prefix length with which to recover.
- Popping a move's source before checking its destination: rejected because destination refusal would require restoring the element to its original position and preserving a source key that may already have been deleted, rather than leaving both entries untouched by admission.
