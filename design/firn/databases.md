Decision: Redis databases 0 through 15 have permanent shared-map identities, with a connection caching its selected map in Keyspace.keys and changing that cache only on SELECT, RESET or a completed EXEC that selected another database, because ordinary keyed commands must retain their existing map-entry access and no additional shared target, instead of looking up a database directory on every command, prefixing key names or exchanging connection handles on SWAPDB. SWAPDB exchanges the two held maps' contents so connected clients keep their logical database identity. Database zero retains its existing map reserve and the fifteen additional maps begin with zero requested reserve, because unused databases must not multiply the original reserve ([database direction and veto](../../research/investigations/firn/connection-waits.md#database-verdict-first)).

Decision: Each context owns an inline record of sixteen shared-map handles, retained individually when the context is cloned and exposed through readonly fields, because the directory needs stable identities for consumer modules while the maps remain mutable under atomic statements, instead of placing the directory behind another shared lock. Frozen cannot hold this record: SHARE-1 excludes shared handles recursively to guarantee an immutable retained value ([pinned specification](https://github.com/Ming-Research/Whitefoot/blob/af7665be672d29912d878dd5da8c3932bb6f296c/spec/kernel-spec.md)). Readonly forbids replacement outside the store module; the store module constructs and clones the directory but never replaces its handles. This uses sixteen map-handle shares per context clone rather than one frozen-handle share, and raises the directory's OP-9 inline size ceiling from 8 to 128 bytes; these are language layout ceilings, not measured frame sizes or elapsed costs. Ordinary GET and SET still use their cached handle without consulting or cloning the directory ([representation witness](../../research/experiments/select-db/shared-handles-witness.wf)).

Decision: EXEC and the whole-database script retry hold all sixteen permanent maps and Meta in one atomic statement, while ordinary network commands and initial declared-key script attempts retain their selected-map paths, because SELECT and computed MOVE, COPY DB or SWAPDB cannot acquire another map halfway through an indivisible execution, instead of releasing and reacquiring holds between commands. Script selection starts in the calling connection's database and stays local to that invocation; EXEC selection becomes the connection's selection. A natural helper receives references to different held maps or entries; compiler rejection stops the dependent implementation rather than introducing alias checks or inlining to hide a language gap ([capability witnesses](../../research/investigations/firn/connection-waits.md#whitefoot-capability-audit-at-the-pin)).

Decision: Queued expiries and script access-undo records carry database identity, access undo deduplicates through sixteen database-local key sets, and FLUSHDB filters only its database's records while SWAPDB replaces both databases' queued expiry records from their swapped contents under the same hold, because an expiry batch may already own records outside Meta when the swap occurs and every moved expiry still needs a queued record, instead of assuming exchanging the pending queue alone accounts for in-flight removals. A stale record removes only a currently present entry with its exact already-due absolute deadline, so it cannot remove a live replacement. Database scope also determines DBSIZE, SCAN, KEYS and RANDOMKEY; global server settings and script sources remain shared.

Decision: Memory pressure releases reserve from all sixteen maps and samples candidates across all databases, preserving database identity in the shared eviction pool and separate resumable absence cursors, because a command on an empty database can still reclaim eligible keys in another database, instead of declaring OOM from the connection's selected database. Global eligibility exhaustion is observed under all sixteen map holds plus Meta; expiry insertions invalidate volatile absence observations. This broader hold is confined to pressure-driven sampling, not ordinary admission with maxmemory zero.

Decision: Database support is accepted only if the single-database comparison detects no per-command regression beyond its twin control, because the owner's database verdict gives the db-0 workload priority over optional logical databases, instead of treating unchanged source lookup shape as a timing result. Compilation, lock-ledger inspection and the AOF-off/on interleaved comparison remain required evidence; a measurable single-db cost retains db 0 only ([predeclared experiment](../../research/investigations/firn/connection-waits.md#performance-experiment-specified-before-implementation)).

Decision: Database-tagged records keep their database invariant and expose all fields as readonly, with store-owned writers declaring the fields each transition changes; shared command encoders enter through store-owned compile-time function adapters that pass only the held log, expiry or random parts to the existing encoder, because the pinned TYPE-11 and TYPE-2 rules require a declaring-module boundary and that boundary proves the unchanged database invariant while scripts retain the same encoders over their private buffers, instead of duplicating command metadata implementations or copying shared logs into temporary buffers. Adapters add source call boundaries without adding database lookups, range checks or shared targets; their inlining and elapsed cost remain CI evidence, not a performance claim ([prescribed proof sites](https://github.com/Ming-Research/Whitefoot/blob/af7665be672d29912d878dd5da8c3932bb6f296c/spec/kernel-spec.md), [minimal invariant witness](../../research/experiments/select-db/type-invariant-writable-field.wf)).
