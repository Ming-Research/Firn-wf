Decision: Pub/sub connection records and channel registries use growing standard hash maps with monotonically allocated u64 registration ids that are never reused during a process, because this follows Redis's dictionary ownership while a stale retained envelope cannot name a later connection, instead of a reusable slab whose initial capacity cannot grow at the pin. The supported process lifetime contains fewer than 2^64 promotions; the id counter's wrap is outside that bound. The separate network-client-id index allows CLIENT LIST to read all three membership counts under its hub snapshot without adding a target to ordinary GET/SET ([registration identities](../../research/investigations/firn/connection-waits.md#registration-identities)).

Decision: Ordinary channels, patterns and shard channels have separate server-wide indexes and owned reverse membership names per connection, because duplicates must acknowledge without adding a delivery path, pattern fanout counts each matching path and shard publication must remain isolated, instead of sharing ordinary and shard namespaces or counting only distinct recipient connections. Pattern matching uses Redis 7.2.16's binary stringmatchlen rules, including its recursive-depth refusal; enumeration order remains unconstrained where Redis exposes dictionary traversal ([pub/sub semantics](../../research/investigations/firn/connection-waits.md#registries-replies-and-restrictions)). Recipient selection and delivery commitment use the event hub ordered with promoted dataset execution by the [connection ownership boundary](connection-ownership.md), so a causally later publication cannot overtake a dataset reply already committed under that hold. Standalone controls observing no dataset state retain only the connection's ordered output commitment; their exact exclusions are owned by that same boundary.

Rejected:
- std Slab: rejected because its fixed capacity at the pin does not fit the selected growing dictionary representation; its explicit-reservation capability is separately requested by firn-req-slab-reserve at P2 and does not block pub/sub.
- A new fixed subscriber ceiling: rejected because the existing client-count option bounds total accepts rather than live registrations and does not provide that semantics.
