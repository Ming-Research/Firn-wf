Decision: A declared-entry script attempt encountering PUBLISH, SPUBLISH, PUBSUB introspection, a potential list producer or a blocking-list command requests the existing uncatchable whole-map retry before observing the registry or selecting recipients, and every whole-map attempt holds the event hub from its start together with the map and Meta, because the declared attempt can undo preceding writes while an already-running whole-map attempt has no general undo boundary for a late wider hold, instead of acquiring the hub inside an atomic body or restarting a written whole-map attempt. Never-promoted declared-only scripts keep their existing targets; promoted scripts start in whole-map mode even for declared-only access to implement the [visibility and reply ordering boundary](connection-ownership.md). Nonpublishing whole-map scripts also take the hub and its contention cost is unmeasured ([script integration](../../research/investigations/firn/connection-waits.md#pubsub-script-attempts)).

Decision: Publications select recipients and counts under the attempt's stable hub hold but retain delivery only in an owned private stage until the final Lua result or error reply is formed, because an abandoned attempt must publish nothing while an accepted Lua error keeps preceding effects, instead of sending on each redis.call or dropping publications when Lua raises. The accepted outer reply group commits before self-publication frames, and publications add no AOF dataset records. Actual staged deliveries prevent budget abandonment; a zero-recipient publication remains retryable because it has no external delivery to duplicate ([atomic publication](../../research/investigations/firn/connection-waits.md#atomic-publication-not-a-wake-race)).

Decision: List readiness remains private to an accepted whole-map script attempt and is drained after the script reply and effects commit, because intermediate pushes may be consumed or deleted within the script and abandoned attempts must awaken nobody, instead of servicing each redis.call separately; blocking-list commands inside a script consume available data or return the nonblocking null form and never register a waiter ([blocking execution units](../../research/investigations/firn/blocking-lists.md#service-boundary)).
