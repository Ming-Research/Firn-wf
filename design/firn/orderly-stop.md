Decision: The never-merged cancellation measurement branch uses the Whitefoot exp/cancel-proto interfaces for an unbounded watched accept and three receive variants, because the owner requested a comparison of real-watch registration, the never-watch path and plain unbounded receive instead of selecting a production cancellation design. The watch and never variants keep the existing nonzero idle-limit deadline and omit it when the limit is zero; the none variant omits every receive deadline. Only a heard stop signal fires the shared source, immediately after recording shutdown; SHUTDOWN still only records the flag. Delayed SHUTDOWN, including a blocked accept, and delayed CONFIG SET idle-limit refresh are accepted experiment regressions; never and none cannot promptly stop unbounded idle receives, and none also omits idle expiry while blocked. Sends retain one-second polling, signal listening retains tenth-second polling, and the client-drain and append-only-file ordering below stay unchanged. This exception is measurement-only and must never merge.

Decision: Outside the never-merged cancellation measurement branch, a shutdown request, recorded in the server's state, reaches every context by polling, because v0.94 joins every spawned context before the entry returns and offers no way to end another context's wait. Every socket wait carries a deadline of at most a second, and each context reads the request where it reads the idle limit. This is instead of a Whitefoot capability that ends other contexts' waits. Measured on the i9-14900K at pipeline depth 1, the receive deadline costs less than the 2% the [orderly-stop investigation](../../research/investigations/orderly-stop/README.md#results) set before measuring as its rejection threshold: at most 1.25%, on `set` on one CPU. This is a stopgap: polling reaches only waits that take a deadline and contexts that come back to their check, so it cannot stop a guarded atomic statement waiting for a state that never comes, work inside an atomic statement, or a host operation without a deadline. A Whitefoot capability that lets one context end other contexts' waits, recorded as a Whitefoot requirement in docs/todo.md, replaces it. The request is kept apart from `Meta.stopping`, and main stops the append-only file's writer only after every client has gone, so the commands clients ran before they saw the request are appended and synced before firn exits. A script that has written runs to its end before its client sees the request ([script execution](scripts.md)), so a script that never ends keeps firn from stopping, as it keeps every other client waiting.

Decision: `SHUTDOWN SAVE` takes Redis 7.0.15's failed-save path, refused unless FORCE is given, because firn writes no snapshot, instead of ignoring SAVE or answering a syntax error.

Decision: SIGTERM and SIGINT request the orderly stop SHUTDOWN requests, through one stop listener that main opens just before it listens and a context of its own waits on, because Redis 7.0.15 shuts down gracefully on either signal under its default `shutdown-on-sigterm` and `shutdown-on-sigint`, appending and syncing its append-only file, instead of the host default, which ends firn at once and loses the changes not yet appended or synced. The context waits at most a tenth of a second at a time and reads the shutdown request between waits, the polling above, because it must also end when firn stops for another reason and nothing else ends its wait, and main's return joins it, so its period adds to firn's exit after a stop for another reason (a one-second period took the network cases from 25 to 59 seconds); main records the request when it stops, so the read needs only the server's state, which a script holding the keyspace's metadata does not hold. A host that refuses the listener stops firn with status 3, as an address it cannot listen on does, instead of serving without the graceful stop.

Decision: On its first signal the context closes its listener before recording the request, restoring the host default, so that any later SIGTERM or SIGINT ends firn at once, because the only way Whitefoot gives a program to end without joining its contexts is the host default, and closing first keeps Redis's escape from a stop that does not finish, a second SIGINT, even while the request waits behind a script that holds the keyspace, instead of keeping the listener through the drain, which would ignore a second SIGTERM as Redis does but leave nothing short of SIGKILL to end firn. A second SIGTERM thus ends firn where Redis ignores it, and a second SIGINT ends it by the signal where Redis exits with status 1.
