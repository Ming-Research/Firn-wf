Decision: A shutdown request, recorded in the server's state, reaches every context by polling, because v0.94 joins every spawned context before the entry returns and offers no way to end another context's wait. Every socket wait carries a deadline of at most a second, and each context reads the request where it reads the idle limit. This is instead of a Whitefoot capability that ends other contexts' waits. Measured on the i9-14900K at pipeline depth 1, the receive deadline costs less than the 2% the [orderly-stop investigation](../../research/investigations/orderly-stop/README.md#results) set before measuring as its rejection threshold: at most 1.25%, on `set` on one CPU. A Whitefoot capability that lets a stop end other contexts' waits would remove even that, and would reopen this choice. The request is kept apart from `Meta.stopping`, and main stops the append-only file's writer only after every client has gone, so the commands clients ran before they saw the request are appended and synced before firn exits. A script that has written runs to its end before its client sees the request ([script execution](scripts.md)), so a script that never ends keeps firn from stopping, as it keeps every other client waiting.

Decision: `SHUTDOWN SAVE` takes Redis 7.0.15's failed-save path, refused unless FORCE is given, because firn writes no snapshot, instead of ignoring SAVE or answering a syntax error.
