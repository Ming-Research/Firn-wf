Decision: A shutdown request stays recorded in the server's state and its requesting context fires one cancellation state shared by main, the client contexts and the signal context, because Whitefoot v0.110 can end their host waits through independently owned watches without a polling deadline, instead of using deadlines to discover shutdown; the accept wait has no deadline and the expiry sleep ends on cancellation. Network command dispatch returns whether it accepted SHUTDOWN, because its caller can then fire its own source without reacquiring server state, instead of waiting on another state read after recording the request. Receive retains a deadline of at most one second provisionally, because live CONFIG timeout changes must reach an already parked receive even when its old limit was zero, instead of ignoring those updates; an independent configuration wakeup reopens this choice ([question and evidence](../../research/investigations/orderly-stop/README.md#live-idle-limit-updates)). The request stays separate from Meta.stopping, and main stops the append-only writer only after every client has gone, because a command already running may still append records before its context ends. A send keeps its never-firing watch and existing one-second deadline logic, because cancelling it would additionally truncate replies that firn currently sends; Redis 7.0.15 promises no flush of ordinary client replies at exit ([send reasoning](../../research/investigations/orderly-stop/README.md#pending-client-replies)). Scripts and guarded waits for their engine remain outside host cancellation ([script execution](scripts.md)).

Decision: `SHUTDOWN SAVE` takes Redis 7.0.15's failed-save path, refused unless FORCE is given, because firn writes no snapshot, instead of ignoring SAVE or answering a syntax error.

Decision: SIGTERM and SIGINT request the orderly stop SHUTDOWN requests through one stop listener that main opens just before it listens and a context of its own waits on without a deadline, because Redis 7.0.15 shuts down gracefully on either under its default shutdown-on-sigterm and shutdown-on-sigint, appending and syncing its append-only file, and the shared shutdown watch ends the signal wait when another context requests shutdown, instead of polling the request every tenth of a second. Main records and fires its own request after the last client leaves when it stops for another reason, including the client limit. Cancellation closes the listener without requesting shutdown again; a host that refuses the listener stops firn with status 3, as an address it cannot listen on does, instead of serving without the graceful stop.

Decision: On its first signal the context closes its listener before recording the request, restoring the host default, so that any later SIGTERM or SIGINT ends firn at once, because the only way Whitefoot gives a program to end without joining its contexts is the host default, and closing first keeps Redis's escape from a stop that does not finish, a second SIGINT, even while the request waits behind a script that holds the keyspace, instead of keeping the listener through the drain, which would ignore a second SIGTERM as Redis does but leave nothing short of SIGKILL to end firn. A second SIGTERM thus ends firn where Redis ignores it, and a second SIGINT ends it by the signal where Redis exits with status 1.

Rejected:
- Propagating shutdown only by polling deadlines: rejected because it cannot end a wait without a deadline, arms a timer for each parked receive and delays exit until the next poll; v0.110 cancellation can end those host waits directly.
