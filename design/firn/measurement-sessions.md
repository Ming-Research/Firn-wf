Decision: A measurement on the shared self-hosted machine runs in a session of its own whose identity, the boot, the session's number and its leader's start time, it records before it starts, registering each server by its process id and start time before the server runs, a registration refused once the record is removed, and the run itself when it ends, or the next run when it was cancelled, stops the leader and every process of the session found while that leader runs, and once it has ended only the registered servers, each signalled through a pidfd opened on the process found, TERM and then KILL, keeping the record and failing the run while any survives or the record does not read, because a cancelled run leaves servers that would load the host a later measurement uses, while the machine also runs other projects' runners and servers that must never be signalled, instead of matching processes by name, by a token in their environment, or by session number and start time alone.

Decision: A process of a measurement's session that is not a server and outlives its leader, such as a client or a profiler, is left to the runner, which stops a job's processes by the tracking variable in their environment, because a session's number can name another session once the leader has ended and only a registered process is known to be the measurement's, while clients and profilers keep the environment the runner reads, instead of stopping every process that still carries the session's number.

Decision: Redis benchmark servers and clients take one logical CPU per distinct physical performance core in Linux topology order, reserving core_id 0 for the OS and runner, with servers first and clients on both threads of the remaining eligible cores, never on a server's core, capping the client count with a warning and recording both lists; without hybrid information the same rule uses all physical cores, and explicit list overrides must preserve physical-core separation and the requested server count, because adjacent logical CPU numbers on the native i9-14900K are hyperthread siblings and later numbers include efficiency cores, instead of assuming consecutive logical CPUs represent independent cores of equal performance.


Decision: Baseline competitors run in compare mode with the same server CPU list, reversed pass order and durability settings as the firn images and their twin, because a comparison against defaults on different resources would not test the [baseline rules](../../research/investigations/perf-baseline/README.md), instead of extending scale mode's fixed-order measurement. Selecting competitors opts into version and archive-provenance checks; a probe may record unverified versions and omit absent Dragonfly or Garnet, but a full run refuses missing provenance, and Dragonfly is refused in AOF cells. Garnet's log-write check establishes logging only, so its AOF line remains labelled durability not equal until the pinned commit path establishes disk synchronization.

Decision: The multi-process compare client divides exactly 50 connections across its assigned CPUs and retains each process's quantiles, reporting their maximum as an explicitly labelled upper bound, because redis-benchmark CSV percentiles cannot reconstruct a merged latency distribution, instead of treating the first process's p99 or an average of percentiles as the combined p99. The single-process threaded client retains its merged histogram; a bound alone cannot establish the baseline's exact p99 verdict ([instrument limits](../../research/investigations/deployment-performance/README.md#compare-baseline-instrument)).

Rejected:
- Matching leftovers by command name: rejected because other projects run the same servers on the machine.
- A token in each process's environment: rejected because Redis 7.0.15 and Valkey overwrite the environment the kernel shows when they set their process titles ([setproctitle.c](https://github.com/redis/redis/blob/7.0.15/src/setproctitle.c)), so the servers a cancelled run leaves escape the match.
- Every process of the recorded session started within hours of its leader: rejected because once the session's processes have all ended its number can be reused by another session, whose processes would then match.
- A PID namespace, a systemd scope or a cgroup per measurement, which would empty itself however the run ends: rejected because the runner's account can create none of them, its user namespaces refused, no user service manager running, sudo barred and its service's cgroup not delegated ([run 37473556611](https://github.com/Ming-Research/Firn-wf/actions/runs/37473556611)); reopen if the runner's service is given a delegated cgroup.
