Decision: A measurement on the shared self-hosted machine runs in a session of its own whose identity, the boot, the session's number and its leader's start time, it records before it starts, and the run itself when it ends, or the next run when it was cancelled, stops exactly the processes of that session started within three hours of the leader, each signalled through a pidfd opened on the process found, TERM and then KILL, keeping the record and failing the run while any survives, because a cancelled run leaves servers that would load the host a later measurement uses, while the machine also runs other projects' runners and servers that must never be signalled, instead of matching processes by name or by a token in their environment.

Rejected:
- Matching leftovers by command name: rejected because other projects run the same servers on the machine.
- A token in each process's environment: rejected because Redis 7.0.15 and Valkey overwrite the environment the kernel shows when they set their process titles ([setproctitle.c](https://github.com/redis/redis/blob/7.0.15/src/setproctitle.c)), so the servers a cancelled run leaves escape the match.
- A PID namespace, a systemd scope or a cgroup per measurement, which would empty itself however the run ends: rejected because the runner's account can create none of them, its user namespaces refused, no user service manager running and sudo barred ([run 37467067049](https://github.com/Ming-Research/Firn-wf/actions/runs/37467067049)); reopen if the runner's service is given a delegated cgroup.
