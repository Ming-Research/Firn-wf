Decision: A command is written as four parts, its parsing, a body over its key's entry (`slot: &Option<Entry>`), or over the entries of the set of keys it names (`&Entries<Entry>`) for a command whose work moves or compares values between keys, such as RENAME and COPY, a metadata step that takes only the expiry metadata and the log it uses and answers how many records it appended, and its reply, with each command's arity stated once, and the network path calls them inside its atomic statement while `script_command` calls the same parts under a script's statement, because a client and a script must run one implementation of a command's semantics and the metadata a command touches decides which objects its statement holds, and both whole-map and declared-entry script adapters can invoke those same bodies (Whitefoot's `&t^[ks]` and `&store^.keys[ks]`, SHARE-2), instead of a second, script-only copy of each command, or a body per key for a command whose keys' work depends on each other.

Decision: `script_command` refuses the commands Redis 7.0.15 marks noscript (AUTH, HELLO, QUIT, RESET, DEBUG, CONFIG, CLIENT, FUNCTION, SHUTDOWN) with Redis's text, and answers every other command it does not run with Redis's unknown-command text extended by a note that firn may know the command and not yet run it from scripts, because the extended text preserves the existing unsupported-command boundary and keeps the words Redis's own tests match, instead of promising script support merely because admission can identify a command.

Decision: command_kind extends the existing held-command identity lookup to network-only commands, and admission, MULTI and scripts share Redis's DENYOOM and WRITE flags keyed by that identity, because memory admission must distinguish unknown names before eviction and script write acceptance differs from actual effects, instead of adding independent identity or flag tables for each execution path; held_kind remains the boundary for commands with atomic parts. This reopens the earlier rejection of identifying unsplit commands: OOM ordering now needs their identity, rather than merely a more specific unsupported-script error.

Decision: Script command planning separates keyless commands, finite ordered operands and whole-map commands after existing admission and parsing, and finite adapters translate command-local operand ranks into immutable declaration ranks, because set algebra and multi-key operations must preserve operand order and duplicates while touching only held entries, instead of using declaration order as command order or supplying a whole-map reference under a declared-entry hold. Commands retain their shared parsing, entry bodies, metadata and replies; EXEC continues to hold the whole map.

Decision: While the keyspace keeps no append-only file, a command's statement that can queue no expiry and reads nothing else from Meta holds only its keys' entries, running the same body with an inert sequence token and skipping the metadata step, and every other statement keeps its Meta target, chosen at run time from the logging setting fixed at startup and, for SET and GETEX, the parsed expiry option, because without a file no writer publishes an error, no rewrite captures and no record is appended, so such a statement needs nothing in Meta, while one exclusive Meta target on every write bounds all writes together by one object's exclusive rate, measured at about 2.8 M one-step holds/s on 8 P-cores of the i9-14900K ([write-meta](../../research/investigations/write-meta/README.md#a-aof-off-writes-hold-no-meta-unless-they-queue-an-expiry)), instead of holding Meta in every write statement whatever the configuration. Statements that can queue or transfer an expiry, that draw from Meta's random state, that hold the whole map, and EXEC and scripts keep Meta in every configuration; the investigation lists the commands of each class ([roster](../../research/investigations/write-meta/README.md#a-aof-off-writes-hold-no-meta-unless-they-queue-an-expiry)). Admission's check for a saved append or sync error, made for every write and PING, also holds no Meta while the keyspace keeps no file, since only the writer, which runs only with a file, saves such an error. This narrows, for AOF off only, the decision in [append-only-file](append-only-file.md) that mutations recheck a saved error under their existing Meta hold.

Decision: A command whose statement holds Meta only on some runs is written as one atomic statement naming its keys and Meta, with every use of Meta under the run-time condition, instead of two statements (one naming Meta, one not) around that condition, because the pinned compiler acquires a named target at its first use on a path, so the path that never uses Meta never holds it, and SET written so measured within the twin's noise at six passes with AOF off on 8 P-cores of the i9-14900K, a median of 0.9965 of the two-statement form per interleaved pass against the twin's 1.001, a cost under 1% not excluded ([write-meta](../../research/investigations/write-meta/README.md#one-statement-set)), while two statements repeat the shell of each such command; the specification only permits holding less than a statement names, so this rests on the compiler's behaviour, which Whitefoot's lock ledger ([Whitefoot#421](https://github.com/Ming-Research/Whitefoot/pull/421)) is to check at each site, and a conditional target in the language, studied in [Whitefoot#418](https://github.com/Ming-Research/Whitefoot/pull/418), is not being added.
