Decision: A command is written as four parts, its parsing, a body over its key's entry (`slot: &Option<Entry>`), or over the entries of the set of keys it names (`&Entries<Entry>`) for a command whose work moves or compares values between keys, such as RENAME and COPY, a metadata step that takes only the expiry metadata and the log it uses and answers how many records it appended, and its reply, with each command's arity stated once, and the network path calls them inside its atomic statement while `script_command` calls the same parts under a script's statement, because a client and a script must run one implementation of a command's semantics and the metadata a command touches decides which objects its statement holds, and a statement holding every key reaches a key set's entries as a statement over that set does (Whitefoot's `&t^[ks]`, SHARE-2), instead of a second, script-only copy of each command, or a body per key for a command whose keys' work depends on each other.

Decision: `script_command` refuses the commands Redis 7.0.15 marks noscript (AUTH, HELLO, QUIT, RESET, DEBUG, CONFIG, CLIENT, FUNCTION, SHUTDOWN) with Redis's text, and answers every other command it does not run with Redis's unknown-command text extended by a note that firn may know the command and not yet run it from scripts, because the extended text preserves the existing unsupported-command boundary and keeps the words Redis's own tests match, instead of promising script support merely because admission can identify a command.

Decision: command_kind extends the existing held-command identity lookup to network-only commands, and admission, MULTI and scripts share Redis's DENYOOM and WRITE flags keyed by that identity, because memory admission must distinguish unknown names before eviction and script write acceptance differs from actual effects, instead of adding independent identity or flag tables for each execution path; held_kind remains the boundary for commands with atomic parts. This reopens the earlier rejection of identifying unsplit commands: OOM ordering now needs their identity, rather than merely a more specific unsupported-script error.
