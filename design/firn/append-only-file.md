Decision: Replay applies the commands between `MULTI` and `EXEC` only once their `EXEC` is read, applies none of a block the file ends inside, passes over an `EXEC` outside a block, and moves a block's start to a nested `MULTI`, as Redis 7.0.15's loader does, because a write cut short leaves an unfinished block that must not apply in part, and scripts and transactions append their effects as blocks.

Decision: The last file whose end did not load is cut before anything is appended: after the last whole command when reading ends inside a command, even inside a block, and before the latest `MULTI` when the file ends cleanly inside a block, and never after a failed read; the server cuts it with `std::fs::truncate_file` before its writer starts and stops with status 4 when the cut fails, as Redis 7.0.15 cuts its file with `aof-load-truncated`, its default, because commands appended after a damaged end would otherwise follow bytes no replay can pass, instead of leaving the damaged end in place. As in Redis, a write appended to that last file after a cut inside an unfinished block is dropped by the next restart. An earlier base or incremental file whose end did not load stops firn with status 4 without cutting it.

Decision: A file that does not load stops firn with status 4 before it listens, leaving the file as it was: a record that is not a well-formed command, a read that fails other than at the file's end, and a block or command larger than the input window's ceiling, as Redis 7.0.15 stops loading and exits on a format error or an unrecoverable read, because serving a keyspace that holds only part of the file, and appending after bytes no replay can pass, loses every later write without notice, instead of starting with the commands read so far.
