Decision: Replay applies the commands between `MULTI` and `EXEC` only once their `EXEC` is read, applies none of a block the file ends inside, passes over an `EXEC` outside a block, and moves a block's start to a nested `MULTI`, as Redis 7.0.15's loader does, because a write cut short leaves an unfinished block that must not apply in part, and scripts and transactions append their effects as blocks.

Decision: The last file whose end did not load is cut before anything is appended: after the last whole command when reading ends inside a command, even inside a block, and before the latest `MULTI` when the file ends cleanly inside a block, and never after a failed read; the server cuts it with `std::fs::truncate_file` before its writer starts and stops with status 4 when the cut fails, as Redis 7.0.15 cuts its file with `aof-load-truncated`, its default, because commands appended after a damaged end would otherwise follow bytes no replay can pass, instead of leaving the damaged end in place. As in Redis, a write appended to that last file after a cut inside an unfinished block is dropped by the next restart. An earlier base or incremental file whose end did not load stops firn with status 4 without cutting it.

Decision: A file that does not load stops firn with status 4 before it listens, leaving the file as it was: a record that is not a well-formed command, a read that fails other than at the file's end, and a block or command larger than the input window's ceiling, as Redis 7.0.15 stops loading and exits on a format error or an unrecoverable read, because serving a keyspace that holds only part of the file, and appending after bytes no replay can pass, loses every later write without notice, instead of starting with the commands read so far.

Decision: Active AOF error handling keeps firn's single appendfsync everysec policy, reopening selectable always and no policies and an appendfsync configuration only when a selected consumer needs them, because the current compatibility experiment needs recoverable write refusal within the existing durability contract, instead of adding unused durability modes and the reply barriers always would require ([investigation](../../research/investigations/aof-write-errors/README.md#proposed-design-and-alternatives)).

Decision: The sole AOF writer publishes separate saved append and sync IoErrors in Meta alongside its byte accounting, and network WRITE commands and PING observe failure at admission while mutations recheck under their existing Meta hold, because Meta already orders every mutation with writer publication and a preflight snapshot alone could admit a mutation after publication, instead of another Shared status object or continuing to acknowledge writes during a known persistence failure; reads and internal expiry or eviction remain allowed, as Redis 7.0.15 server.c:3881-3905,4324-4353 requires.

Decision: An incomplete append attempts truncation to the pre-flush incremental size, retaining the whole buffer on successful rollback or accounting the accepted prefix and retaining its suffix on failed rollback, and only a complete append clears its saved error, because Redis 7.0.15 aof.c:1146-1230 preserves exactly the bytes that still need writing, instead of always leaving a partial record in the file; the actual terminal IoError and whether the result was partial remain available so later error formatting can preserve Redis's ENOSPC normalization for partial results without discarding the host error.

Decision: Failed appends are retried about once per second without new client writes, as Redis 7.0.15 server.c:1384-1393 does, and failed syncs are likewise retried while idle and cleared on success, because otherwise disk recovery can leave an idle server permanently refusing writes, instead of Redis's new-byte-dependent everysec sync resubmission in aof.c:1067-1089,1255-1261; a sync failing with EINVAL counts as success and latches nothing, as Redis's bio.c:235-247 treats it, so a file that cannot be synchronized does not refuse writes; idle sync retry is a deliberate difference from Redis ([method and rejection criteria](../../research/investigations/aof-write-errors/README.md#method-and-rejection-criteria-before-implementation)).

Decision: A rewrite's new incremental file resets only its incremental-size accounting and preserves append and sync health except when a completed append or sync clears its own error, because Redis 7.0.15 openNewIncrAofForAppend in aof.c:790-852 preserves those states, instead of applying startAppendOnly's CONFIG re-enable reset in aof.c:999-1013 to ordinary rotation.

Decision: All persistence refusals use one reply writer that emits Redis's exact MISCONF prefix followed by the host's description of the saved IoError, copied by std::io::error_copy_description into the reply window and sized from the length the host reports, selecting a failed append's own error when nothing of that append was written and otherwise the sync error, as Redis 7.0.15 writeCommandsDeniedByDiskError selects aof_last_write_errno (server.c:4324-4355, aof.c:1157-1162), because PRE-2's description of a host code is the host C library's C-locale message, the text Redis formats with strerror, instead of an errno-to-text table or an invented suffix that would conceal a language gap. A short write, which Redis reports as ENOSPC whatever the host returned (aof.c:1163-1184), and a description the host reports unavailable leave the suffix empty, because std names no host code for ENOSPC (Whitefoot item firn-req-enospc-text) and an empty suffix states no text the host did not give, instead of describing the short write's terminal error or substituting PRE-2's code-zero fixed text ([investigation](../../research/investigations/aof-write-errors/README.md#misconf-description-whitefoot-v0132)).
