Decision: Where firn reports facts about itself in Redis's form, as INFO and CLIENT INFO do, a field firn has carries its real value, a field whose value is fixed for firn carries that value, and a field firn cannot measure is left out, because clients already read these replies field by field and allow for fields that differ between Redis versions, ssub added in 7.0 and lib-name in 7.2 among them, while an invented value would be a false report that a client or an operator could act on, instead of a placeholder for every field Redis gives or a refusal until firn measures them all.

Decision: CLIENT LIST gives the connection that runs it every field CLIENT INFO gives, and gives every other connection the fields that change only when that connection sets one, its id, addresses, name, age, database, user, tracking redirection, protocol and library name and version, with the subscription counts the event hub already keeps for its pub/sub registries, leaving out idle, flags, multi and cmd for it, because those four follow a connection's latest command and a connection could publish them only by writing a table all connections share on every command, which costs every command a contended write on the hot path, while a connection publishes the facts it sets once per change

Decision: A connection's address that the host refuses to report is shown empty, as addr= or laddr= with nothing after the equals sign, because Redis 7.2.16's genClientAddrString does the same when connAddr fails, leaving its zeroed buffer unwritten, and the placeholder ?:0 its comment promises is what the first decision rejects

Rejected:
- Publishing a connection's subscription counts to the table of clients with the facts it sets: rejected because the event hub's registries already keep them and pubsub-registries has CLIENT LIST read them there under its hub snapshot, so a second copy would be written by every membership change and could disagree with the hub.
- Placeholder values for the fields firn cannot measure, such as addr=?:0 or used_memory:0: rejected because nothing tells a reader them from measurements.
- Refusing INFO or CLIENT INFO until firn measures every field: rejected because a selected consumer's client sends CLIENT INFO ([consumers](https://github.com/Ming-Research/Firn-wf/blob/fab3ed5b411f61bd2f8eb85f4a2c29f4582f4a91/research/investigations/consumers/README.md#what-the-milestone-needs-from-firn)) and Django's test fails on the refusal, while it reads no field firn leaves out.
- Publishing idle, flags, multi and cmd to the table of clients on every command so that CLIENT LIST gives them for every connection: rejected because it adds a shared write to every command of every connection, against firn's throughput goal. Firn's supported normal connections expose these fields only on the calling connection's line. Redis's suite also checks another replica's flags=S ([maxmemory](https://github.com/redis/redis/blob/7.2.16/tests/unit/maxmemory.tcl#L294)) and checks flags=O is absent from the whole list after resetting a monitor connection ([other](https://github.com/redis/redis/blob/7.2.16/tests/unit/other.tcl#L319)); replication and MONITOR are outside firn's supported features, so these checks do not justify a per-command shared write for its normal connections.
